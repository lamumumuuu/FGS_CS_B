## 3. 连接配置

### 3.1 连接字符串格式

#### 3.1.1 JDBC URL 格式

```
jdbc:postgresql://<host>:<port>/<database>?<参数1>=<值1>&<参数2>=<值2>
```

#### 3.1.2 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| host | 数据库主机地址 | localhost |
| port | 数据库端口 | 5432 |
| database | 数据库名称 | postgres |

#### 3.1.3 完整连接示例

```
jdbc:postgresql://localhost:5432/computer_association?useUnicode=true&characterEncoding=utf8
```

### 3.2 Spring Boot 配置

#### 3.2.1 YAML 配置 (application.yml)

```yaml
spring:
  datasource:
    url: jdbc:postgresql://${DB_HOST:localhost}:${DB_PORT:5432}/${DB_NAME:postgres}
    username: ${DB_USERNAME:postgres}
    password: ${DB_PASSWORD}
    driver-class-name: org.postgresql.Driver
```

#### 3.2.2 环境变量配置 (.env)

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=postgres
DB_USERNAME=postgres
DB_PASSWORD=123456
```

### 3.3 连接池配置

本项目使用 Spring Boot 默认的 HikariCP 连接池，常用配置如下：

```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 20        # 最大连接数
      minimum-idle: 5              # 最小空闲连接数
      connection-timeout: 30000    # 连接超时时间（毫秒）
      idle-timeout: 600000         # 空闲连接超时时间（毫秒）
      max-lifetime: 1800000        # 连接最大生命周期（毫秒）
      pool-name: ComputerAssociationHikariPool
```

## 5. 安全认证方式

### 5.1 数据库用户权限

#### 5.1.1 权限规划

| 用户角色 | 权限范围 | 使用场景 |
|----------|----------|----------|
| 超级用户 (postgres) | 全部权限 | 数据库初始化、建表 |
| 应用用户 | SELECT, INSERT, UPDATE, DELETE | 后端应用连接 |
| 只读用户 | SELECT | 数据报表、查询分析 |

#### 5.1.2 创建应用用户（推荐）

```sql
-- 创建用户
CREATE USER app_user WITH PASSWORD 'your_strong_password';

-- 创建数据库
CREATE DATABASE computer_association OWNER app_user;

-- 授予连接权限
GRANT CONNECT ON DATABASE computer_association TO app_user;

-- 授予 schema 权限
GRANT USAGE ON SCHEMA public TO app_user;

-- 授予表权限（根据需要）
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_user;

-- 授予序列权限
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_user;

-- 设置默认权限
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_user;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT USAGE, SELECT ON SEQUENCES TO app_user;
```

### 5.2 密码安全策略

- **密码强度**: 至少 12 位，包含大小写字母、数字和特殊字符
- **存储方式**: 使用环境变量或密钥管理服务，禁止硬编码
- **定期更换**: 建议每 90 天更换一次数据库密码
- **访问控制**: 限制数据库访问来源 IP 地址

### 5.3 网络安全

- **本地开发**: 使用 localhost 或 127.0.0.1 访问
- **生产环境**:
  - 使用 SSL/TLS 加密连接
  - 配置 pg_hba.conf 限制访问 IP
  - 使用 VPC 或内网连接，避免暴露公网

### 5.4 SSL 连接配置（生产环境推荐）

```yaml
spring:
  datasource:
    url: jdbc:postgresql://${DB_HOST}:${DB_PORT}/${DB_NAME}?ssl=true&sslmode=verify-full
    hikari:
      data-source-properties:
        ssl: true
        sslmode: verify-full
```

## 6. 数据库表结构

### 6.1 用户表 (users)

#### 6.1.1 表结构

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | SERIAL | PRIMARY KEY | 主键，自增 |
| username | VARCHAR(50) | NOT NULL, UNIQUE | 用户名 |
| email | VARCHAR(100) | NOT NULL, UNIQUE | 邮箱 |
| password | VARCHAR(100) | NOT NULL | 加密后的密码 |
| avatar | VARCHAR(255) | NULL | 头像 URL |
| role | INTEGER | DEFAULT 0 | 角色：0-普通用户，1-干事，2-管理员 |
| status | INTEGER | DEFAULT 1 | 用户状态：0-禁用，1-启用 |
| create_time | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| update_time | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 更新时间 |
| last_login_time | TIMESTAMP | NULL | 最后登录时间 |

#### 6.1.2 索引

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| idx_users_username | username | BTREE | 用户名单列索引 |
| idx_users_email | email | BTREE | 邮箱单列索引 |
| idx_users_status | status | BTREE | 状态单列索引 |

#### 6.1.3 建表 SQL

```sql
-- 创建用户表
CREATE TABLE IF NOT EXISTS users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    password VARCHAR(100) NOT NULL,
    avatar VARCHAR(255),
    role INTEGER DEFAULT 0,
    status INTEGER DEFAULT 1,
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_login_time TIMESTAMP
);

-- 添加索引
CREATE INDEX IF NOT EXISTS idx_users_username ON users(username);
CREATE INDEX IF NOT EXISTS idx_users_email ON users(email);
CREATE INDEX IF NOT EXISTS idx_users_status ON users(status);
```

## 8. 数据库版本管理

### 8.1 Liquibase 简介

Liquibase 是一个开源的数据库版本管理工具，支持：
- 跟踪数据库变更历史
- 自动执行数据库迁移脚本
- 支持多种数据库
- 支持回滚操作

#### 8.2.1 YAML 配置

```yaml
spring:
  profiles:
    include: liquibase
```

#### 8.2.2 Liquibase 配置文件

[application-liquibase.yml](file:///c:/Users/admin/Desktop/fgs2026-01-24-service-master/src/main/resources/application-liquibase.yml)

#### 8.2.3 变更日志文件

| 文件 | 说明 |
|------|------|
| [db.changelog-master.xml](file:///c:/Users/admin/Desktop/fgs2026-01-24-service-master/src/main/resources/db/changelog/db.changelog-master.xml) | 主变更日志 |
| [db.changelog-1.0.xml](file:///c:/Users/admin/Desktop/fgs2026-01-24-service-master/src/main/resources/db/changelog/db.changelog-1.0.xml) | 1.0 版本变更 |

### 8.3 变更日志格式

```xml
<?xml version="1.0" encoding="UTF-8"?>
<databaseChangeLog
    xmlns="http://www.liquibase.org/xml/ns/dbchangelog"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:schemaLocation="http://www.liquibase.org/xml/ns/dbchangelog
                      http://www.liquibase.org/xml/ns/dbchangelog/dbchangelog-3.10.xsd">

    <changeSet id="1.0" author="developer">
        <sqlFile path="sql/Users.sql" splitStatements="true" stripComments="true"/>
    </changeSet>

</databaseChangeLog>
```

### 8.4 添加新变更步骤

1. 在 `src/main/resources/db/changelog/` 下创建新的变更文件（如 `db.changelog-1.1.xml`）
2. 在 `db.changelog-master.xml` 中引入新文件
3. 启动应用时 Liquibase 会自动执行未执行的变更

## 9. 数据备份与恢复流程

### 9.1 备份策略

| 备份类型 | 频率 | 保留时间 | 适用场景 |
|----------|------|----------|----------|
| 全量备份 | 每日凌晨 | 30 天 | 数据灾难恢复 |
| 增量备份 | 每小时 | 7 天 | 数据误操作恢复 |
| 手动备份 | 按需 | 永久 | 版本发布前、重大变更前 |

### 9.2 全量备份

#### 9.2.1 使用 pg_dump 备份

```bash
# 备份整个数据库
pg_dump -h localhost -U postgres -d computer_association -F c -f backup_$(date +%Y%m%d).dump

# 备份为 SQL 格式
pg_dump -h localhost -U postgres -d computer_association -F p -f backup_$(date +%Y%m%d).sql
```

#### 9.2.2 参数说明

| 参数 | 说明 |
|------|------|
| -h | 主机地址 |
| -U | 用户名 |
| -d | 数据库名 |
| -F | 输出格式（c=自定义，p=SQL 文本） |
| -f | 输出文件名 |

#### 9.2.3 Windows 备份脚本

```powershell
# backup.ps1
$timestamp = Get-Date -Format "yyyyMMdd_HHmmss"
$backupFile = "C:\backup\db_backup_$timestamp.dump"
$pgDumpPath = "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe"

& $pgDumpPath -h localhost -U postgres -d computer_association -F c -f $backupFile

if ($LASTEXITCODE -eq 0) {
    Write-Host "备份成功: $backupFile"
} else {
    Write-Host "备份失败"
}
```

### 9.3 数据恢复

#### 9.3.1 使用 pg_restore 恢复

```bash
# 恢复自定义格式备份
pg_restore -h localhost -U postgres -d computer_association -c backup_20240101.dump

# 恢复 SQL 格式备份
psql -h localhost -U postgres -d computer_association -f backup_20240101.sql
```

#### 9.3.2 参数说明

| 参数 | 说明 |
|------|------|
| -c | 恢复前删除已存在的对象 |
| -d | 目标数据库名 |

### 9.4 备份验证

```bash
# 验证备份文件是否有效
pg_restore -l backup_20240101.dump
```

### 9.5 自动备份配置（Linux）

```bash
# 添加 crontab 任务，每天凌晨 2 点备份
0 2 * * * /usr/bin/pg_dump -U postgres -d computer_association -F c -f /backup/db_backup_$(date +\%Y\%m\%d).dump

# 清理 30 天前的备份
0 3 * * * find /backup -name "db_backup_*.dump" -mtime +30 -delete
```

## 10. 常见问题排查

### 10.1 连接失败问题

#### 10.1.1 Connection refused

**现象**:
```
org.postgresql.util.PSQLException: Connection to localhost:5432 refused.
```

**可能原因**:
1. PostgreSQL 服务未启动
2. 端口号错误
3. 防火墙阻止连接

**排查步骤**:
```bash
# 1. 检查 PostgreSQL 服务状态
# Windows
netstat -ano | findstr 5432

# Linux
ps aux | grep postgres
netstat -tlnp | grep 5432

# 2. 检查端口是否可访问
telnet localhost 5432
```

**解决方法**:
- 启动 PostgreSQL 服务
- 检查配置文件中的端口号
- 配置防火墙允许 5432 端口

#### 10.1.2 密码认证失败

**现象**:
```
org.postgresql.util.PSQLException: FATAL: password authentication failed for user "postgres"
```

**排查步骤**:
1. 确认用户名和密码正确
2. 检查 pg_hba.conf 认证方式配置
3. 验证环境变量是否正确加载

**解决方法**:
- 重置数据库用户密码
- 检查 .env 文件配置
- 确认 Spring Boot 正确读取了配置

### 10.2 性能问题

#### 10.2.1 查询慢

**排查步骤**:
```sql
-- 1. 查看慢查询日志
-- 2. 使用 EXPLAIN 分析查询计划
EXPLAIN ANALYZE SELECT * FROM users WHERE username = 'test';

-- 3. 检查索引是否存在
SELECT * FROM pg_indexes WHERE tablename = 'users';
```

**常见原因**:
- 缺少索引
- 查询条件未走索引
- 连接池配置不合理

#### 10.2.2 连接池耗尽

**现象**:
```
HikariPool-1 - Connection is not available, request timed out after 30000ms.
```

**排查步骤**:
1. 检查连接池配置
2. 查看是否有连接泄漏
3. 监控活跃连接数

**解决方法**:
- 增大 maximum-pool-size
- 检查代码中是否正确关闭连接
- 优化慢查询

### 10.3 其他常见问题

#### 10.3.1 字符集问题

**现象**: 中文乱码

**解决方法**:
```sql
-- 查看数据库字符集
SELECT datname, pg_encoding_to_char(encoding) FROM pg_database WHERE datname = 'computer_association';

-- 创建数据库时指定字符集
CREATE DATABASE computer_association WITH ENCODING 'UTF8';
```

#### 10.3.2 序列值不一致

**现象**: 插入数据时主键冲突

**解决方法**:
```sql
-- 重置序列值
SELECT setval('users_id_seq', (SELECT MAX(id) FROM users));
```

```bash
# 使用 Maven 插件执行
./mvnw liquibase:update
```

### 11.5 使用 pgAdmin 操作数据库

#### 11.5.1 连接数据库

1. 打开 pgAdmin 4
2. 在左侧面板右键 "Servers" -> "Register" -> "Server"
3. 填写连接信息：
   - Name: 本地 PostgreSQL
   - Host: localhost
   - Port: 5432
   - Username: postgres
   - Password: 你的密码
4. 点击 "Save"

#### 11.5.2 查询数据

1. 展开数据库 -> Schemas -> public -> Tables
2. 右键点击表名 -> "View/Edit Data" -> "All Rows"
3. 查看或编辑数据

#### 11.5.3 执行 SQL

1. 点击工具栏 "Tools" -> "Query Tool"
2. 输入 SQL 语句
3. 点击执行按钮（或按 F5）

### 11.6 数据导出导入

#### 导出单表

```bash
# 导出 users 表
pg_dump -U postgres -d computer_association -t users -F p -f users_table.sql
```

#### 导入数据

```bash
# 导入 SQL 文件
psql -U postgres -d computer_association -f users_table.sql
```
